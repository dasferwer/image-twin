# Устройство ImageTwin

## Загрузка без потери состояния

API проверяет владельца, размер файла и SHA-256. Pillow читает заголовок,
проверяет размеры, применяет ориентацию EXIF и сохраняет обычный RGB PNG.
Hash размеров и пикселей используется для точной дедупликации.

Под блокировкой коллекции создаются image и связь с ключом загрузки.
Это происходит до обращения к S3. Запись uploading хранит путь и lease.
Если S3 недоступно, запись остаётся, lease освобождается и тот же запрос
может повторить загрузку. При потере ответа после commit повтор возвращает
уже существующее изображение. Изменение файла при том же ключе даёт 409.

После успешного PUT в S3 статус pending и событие uploaded коммитятся вместе.
Worker видит только такие записи. Файл повторно проверяется по SHA-256 при
чтении. Автоматического удаления осиротевших uploading-записей нет: клиент
должен повторить запрос с исходным файлом. Для длительной работы нужен GC.

## Индексация

Dispatcher выбирает pending и просроченные задания через SKIP LOCKED.
Новое поколение token и lease фиксируются в БД, затем ID публикуется в
quorum-очередь RabbitMQ с publisher confirms. Потерянная публикация будет
повторена после lease.

Worker забирает только queued с подходящим token. pHash, вектор, ORB-точки,
дескрипторы, статус ready и событие indexed сохраняются одной транзакцией.
Повтор сообщения не создаёт второй commit. Старый worker не может записать
результат после нового поколения или удаления изображения.

## Признаки и поиск

- pHash: DCT изображения 32×32, блок 8×8, 64 бита; DC-компонента не используется
  для выбора медианы и обнуляется в hash.
- Вектор: MobileNetV2, RGB 224×224, нормализация ImageNet, global average pooling,
  1280 компонент с L2-нормировкой. Файл модели проверяется по SHA-256.
- ORB: до 600 точек на изображении с длинной стороной не более 640 пикселей.
  Координаты хранятся в долях ширины и высоты.

Из коллекции берутся 40 ближайших векторов и 40 ближайших hash. Объединение
содержит не более 80 кандидатов. Cosine distance считает pgvector; поиск
векторов здесь точный по коллекции, без HNSW. При лимите 500 изображений
такой вариант остаётся понятным и воспроизводимым. Для больших коллекций
потребуются другой индекс и измерение recall отбора кандидатов.

Результат подтверждается одним из двух правил:

1. Hamming distance ≤ 8, cosine similarity ≥ 0.92, достаточный контраст обоих снимков.
2. Минимум 12 ORB-inliers, доля inliers ≥ 0.5, площадь совпавшей области ≥ 0.06
   на обоих изображениях. Отбор дескрипторов использует ratio test 0.7;
   homography проверяется RANSAC с допуском 0.012 в нормализованных координатах.

В ответе возвращаются эти значения. Подтверждение пары не означает, что
все изображения, связанные цепочкой похожести, являются копиями друг друга.
Автоматическая кластеризация по транзитивности не применяется.

## Удаление и повторная обработка

Удаление сначала меняет статус и убирает признаки из PostgreSQL, затем
удаляет объект в S3. Даже если S3 отвечает с ошибкой, изображение больше
не участвует в поиске; ответ содержит `object_removed=false`. Повторный DELETE
повторяет очистку. Во время uploading удаление отклоняется, чтобы загрузчик
не записал объект после его удаления.

Reindex доступен для ready и failed: он очищает старые признаки и ставит
задание заново, сохраняя image ID. Результаты разных encoder_version не
сравниваются. При смене модели нужно переиндексировать нужные коллекции.

## Границы

PNG/JPEG, один кадр, от 32 пикселей на сторону, до 4 млн пикселей и 10 МиБ
исходного файла. Лимит коллекции — 500 активных изображений. Повторные
клиентские ключи и tombstone-записи хранятся без автоматического retention.

Водяной знак, сильная обрезка, однотонный фон, повторяющаяся текстура или
несколько снимков одинакового предмета могут привести к ошибке. Измерения
на восьми снимках нельзя переносить на произвольный товарный каталог.

Источники: [ONNX MobileNet](https://github.com/onnx/models/tree/main/validated/vision/classification/mobilenet),
[OpenCV feature matching](https://docs.opencv.org/4.x/d5/d6f/tutorial_feature_flann_matcher.html),
[OpenCV homography](https://docs.opencv.org/4.x/d7/dff/tutorial_feature_homography.html).
